# 不同类型的项目怎样使用同一工作空间

管理目录回答问题、范围、版本和证据；工程类型决定构建、运行和交付方式。不要为每种技术栈再复制一套需求状态和版本台账。

| 类型 | 10-code保存 | outputs或受控存储保存 | 至少核对 |
| --- | --- | --- | --- |
| Web前端/API | 页面、服务、测试与配置 | 静态包、镜像、部署产物 | 路由、资源、API、鉴权与持久化 |
| 手机App | 原生或跨端工程、资源与测试 | 安装/提交包 | 设备安装、签名、权限、升级、数据兼容 |
| 桌面App | 桌面工程、安装与测试脚本 | 安装器、便携包 | 目标系统、安装更新、文件权限与恢复 |
| 插件/CLI/SDK | 实现、契约、示例与测试 | 插件包、可执行或发行包 | 宿主/命令/接口实际使用及版本兼容 |
| Agent/自动化 | 提示词源、工具、工作流、评测集定义 | 执行记录、评测与导出 | 权限、费用、资料外传、失败恢复与真实任务效果 |
| 内容/设计工程 | 编辑源、模板和生成脚本 | PDF、演示、成片等 | 导出完整性、可读性、素材来源与交付质量 |

## 工程登记示意

以下仅解释字段，实际初始化的components为空。真实创建后才登记：

```json
{
  "id": "example-component",
  "type": "web",
  "source": "10-code/example-component",
  "commands": {"build": ["npm", "run", "build"]}
}
```

source须在10-code下，命令为参数数组，不能以组件名拼任意shell路径。框架锁文件、运行版本、测试与必要产物规则也应在项目定义时明确。清单有执行能力，陌生仓库的清单必须审查，不盲跑。

## CI与平台

当前模板CI只验证通用Python脚手架。App需真实设备或平台Runner，iOS不因Windows模板检查通过就算可构建；Agent需可用服务与任务评测；内容工程需实际导出与视觉核对。未配置的环境写未覆盖。

## 真实数据

数据库、上传文件、用户媒体、证书私钥和账户属于独立保管范围。不要为了“完整工作空间”就把它们公开，也不要为了清理目录而移动应用正在使用的数据根。
