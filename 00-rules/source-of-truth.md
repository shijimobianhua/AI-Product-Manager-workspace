# 唯一事实源

每类持续更新的信息只维护一处，其他地方引用。文件越多越需要明确谁负责，而不是复制更多“最新版”。

| 信息 | 唯一维护位置 |
| --- | --- |
| 目录职责及图示数据 | directory-map.json；README和图片是说明视图 |
| 原始输入身份与来源 | 01-inputs/source-register.md |
| 产品背景、术语、环境身份 | 02-product/ |
| 跨需求规划与取舍 | 03-planning/ |
| 需求当前状态、负责人、优先级、目标版计划 | 04-requirement-pool/requirement-pool.md |
| 单需求范围与验收定义 | 05-requirements/对应工作包/prd.md |
| 正式版本范围 | 06-versions/版本/scope.md |
| 当前环境正在服务哪个目标 | 06-versions/deployment-register.md |
| 产物与源码保管的实际位置 | 06-versions产物/保管收据及登记 |
| 历史评审、执行、失败、回退事实 | 07-reviews/ |
| 组件身份、路径与可执行命令 | 根workspace.yaml |
| 已提交的工程与管理文档历史 | 根Git仓库 |

PRD描述“应该怎样”，代码体现“现在怎样实现”，测试说明“验证过什么”，三者冲突要记录差异，不能自动任选一份当批准结论。历史归档、生成快照和说明图不会自动成为新的当前事实。

复制到GitHub的文档不要链接被忽略的本地文件，改为引用可提交收据。私有payload缺席不等于丢失，只要记录访问范围和恢复方法；没有实际副本时不能假称已备份。
